## 一、现状与约束

### 1.3 数据约束（决定方案边界）

当前 `HOMEWORK` 的班级对象只有：

```js
{ cls, submitted, total, accuracy, time, status, ebook, unsub }
```

仅凭这些字段，**只能算出提交率和平均得分率两个指标**——列表页数据不足以支撑报告。但按生产截图（见 1.4），学生级成绩与题级错题在讲评页已具备，因此报告的数据源**不是列表页的 `HOMEWORK`，而是与讲评页同源的学情数据**；报告侧真正的缺口见 9.3。

另一个现实问题：mock 数据中存在 `total: 1`、`total: 3`、`submitted: 1 / total: 14` 的极小班级。这些班级做统计分析报告没有意义，方案中必须有**小样本保护**规则（见 8.1）。

### 1.4 与生产讲评页的对照：边界与复用

生产讲评试卷页的「班级对比」tab 目前只有一张聚合表（2026-10 截图确认）：

- **表头口径**：作业满分、作业平均分、已交人数、未交人数（含「异常学号卡？」标注）、未交名单（查看全部）
- **等级口径**：优秀 / 良好 / 及格 / 低分四档，阈值经「设置等级」可改（默认 优秀≥90%、良好≥80%、及格≥60%、低分<30%）
- **表列**：班级、任课教师、已交人数、未交人数、最高分、最低分、平均分（分数+排名）、优秀/良好/及格/低分（人数+率）
- **表行**：年级行 + 所选班级行；教师端班级筛选只见本班——权限已在数据层收敛，与本报告权限矩阵一致
- **视图**：表格 ↔ 柱状图、手动分组统计、导出

**这张表结构性上给不了的六类信息**（即报告的增量所在）：

| # | 缺失信息 | 原因 | 报告对应模块 |
|---|---|---|---|
| 1 | 分布形态（双峰 / 断层带 /  gaps） | 只有档位聚合计数，无分布形状 | R1 模块 2 直方图 |
| 2 | 题级得分率与讲评阈值判定 | 表粒度为班级 × 等级，无题维度 | R1 模块 3、6 |
| 3 | 知识点 / 错因下钻 | 同上 | R1 模块 4、5 |
| 4 | 时间轴：与上次对比、趋势、下跌预警 | 单次快照（本版不做，单次口径不承诺） | — |
| 5 | 结论产出：讲评清单、教学建议、跟进闭环 | 表不产出动作 | R1 模块 6、7、9 |
| 6 | 管理分析层：显著性、质量判定、督导与教研落点 | 无 | R3 / R4 全部 |

第 1 项最易被低估：档位数与分布形状是两回事。「优秀 3 人 + 低分 5 人」与「同样档位数但中间存在空档带」对应完全不同的讲评策略（全体重讲 vs 分层讲），档位计数回答不了这个问题。

**应复用而非重建**（生产已具备）：

| 生产已有 | 报告侧做法 |
|---|---|
| 等级四档阈值与「设置等级」入口 | 报告读取同一份配置，不自设档位 |
| 未交名单（查看全部） | R1 模块 1 未交展开直接链接，不另维护名单 |
| 「异常学号卡？」标注 | 继承为报告「数据质量说明」区的口径 |
| 手动分组统计 | 分层作业 / 分组分析复用该教师分组，不另建分层名单 |
| 表格 ↔ 柱状图、导出交互 | 组件级复用 |

**结论**：讲评页出「是什么」（描述性统计层），报告出「怎么看、为什么、怎么办」（分析与结论层）。两者共用数据源与阈值配置，报告不重做这张聚合表。组长登录时该表展开全部班级行，已是 R3 的最薄骨架；报告层在其上叠加分析列（显著性 / 均分差 / 质量判定），而非另起一张表。

截图案例本身（已交 1 人 / 满分 91 / 平均分 12）即 8.1 小样本保护必须拦截的场景：该样本量下排名、各档率均无统计意义。

## 二、设计原则：两个角色关心的根本不是一件事

| | 学科教师 | 领导（学科组长 / 教务） |
|---|---|---|
| 打开报告的时机 | 课前 10 分钟备课、课堂讲评中 | 周教研会、月度质量分析 |
| 核心问题 | **这节课我讲什么、找谁、练什么** | **质量是否均衡、谁需要督导、教研抓什么** |
| 关注对象 | 具体的题、具体的学生 | 班级之间、教师之间 |
| 期望产出 | 一份可直接用的讲评清单 | 一组可执行的管理动作 |
| 信息密度 | 低——结论先行，能一屏看完最好 | 中高——需要交叉分析和统计依据 |
| 时间压力 | 极高（课堂节奏） | 中（会议节奏） |

**由此推出的两条设计主线：**

- **教师版 = 行动导向**：每个模块都要收敛到「所以我该做什么」。逐题下钻、学生名单、讲评清单、一键加入题篮——都是为了让教师不用二次加工就能上课。
- **领导版 = 异常导向 + 决策支撑**：不呈现教学细节，只呈现偏差、差异和判定。判定必须给出规则依据，不能是黑箱结论。

**R3 的定位需要特别说明**：领导点某个班的「班级报告」，他不关心这个班的逐题讲评顺序（那是任课教师的事），他关心的是**这个班在全年级坐标系里的位置、差异是否显著、要不要介入**。所以 R3 本质是「从年级视角切入的单班质量诊断」，而非 R1 的删减版。

## 三、R1 · 班级报告（学科教师版）

模块顺序即课堂准备顺序：概况 → 讲什么 → 找谁 → 练什么。

### 模块 0 · 报告头

`作业名 · 班级 · 学科 · 作业类型 · 批阅时间 · 样本口径`

样本口径必须显式写出：**应交 N / 实交 M / 有效 K**（有效 = 剔除空白卷与异常卷后）。教师要知道结论建立在多少份卷子上。

### 模块 1 · 一眼概况（KPI 大数卡 ×6）

| 指标 | 口径 | 附加信息 |
|---|---|---|
| 提交率 | submitted / total | 未交名单可展开 |
| 平均得分率 | 班级均分 / 卷面满分 | 与年级均差 ±pp |
| 优秀率 | 得分率 ≥ 85% 人数占比 | 与年级占比差 |
| 及格率 | 得分率 ≥ 60% 人数占比 | 与年级占比差 |
| 低分率 | 得分率 < 40% 人数占比 | 与年级占比差 |
| 用时中位数 | 学生答题时长中位数 | 年级中位数对比 |

每张卡片下方一行小字给年级参照（↑/↓ + pp 差值），教师第一个问题永远是「我的班这次在年级里什么位置」。

> ⚠️ 用时数据当前不存在，`time` 字段是提交时间戳而非答题时长，需新增（见 6.2）。

### 模块 2 · 得分分布

分布直方图（本班柱 + 年级曲线叠加）+ 等级明细表。**等级档位沿用生产「设置等级」的四档口径**（默认 优秀≥90% / 良好≥80% / 及格≥60% / 低分<30%，校级可配），报告不自设第二套档位。

每档列出：人数、班级占比、年级占比、差值（正绿负红）。

直方图与档位表不冗余：生产班级对比表已提供各档聚合计数，报告补的是**分布形状**——分数是集中还是两极、中间有无断层带。这决定讲评策略是「全体重讲」还是「分层讲」，档位计数回答不了这个问题（见 1.4）。

**这个模块解决的是教学策略分叉**：整体偏低 → 普遍性问题，需重讲；两极分化 → 分层教学，讲评课要分开设计。两种情况的处理方式完全不同，所以分布图必须放在逐题分析之前。

### 模块 3 · 逐题得分率 ⭐核心

- 横轴题号，纵轴得分率，**本班柱 + 年级线**双序列
- 低于讲评阈值的柱体标红
- 筛选开关：「只看需讲评题」（班级得分率 < 70%）
- **点击柱体下钻**，展开该题面板：
  - 选项分布（客观题）/ 得分点命中率（主观题）
  - 主错因标签
  - 做错本题的学生名单（可直接勾选加入补练）

这是教师使用频率最高的模块，交互必须一次点击到位。

### 模块 4 · 知识点诊断

- 掌握率**升序**排行（最弱在最上，教师从上往下看即可）
- 三级标签：未掌握 < 60% / 薄弱 60–80% / 掌握 ≥ 80%
- 特殊标记：
  - 「全班薄弱」：本次班级掌握率 < 60%
- 每个知识点关联题号，点击跳转到模块 3 对应柱体

### 模块 5 · 错因聚类

环形图 + 明细表（错因 / 人次 / 涉及题数 / 涉及人数 / 失分合计）。
单次作业口径：只统计本次作业错因，不做跨次叠加。

### 模块 6 · 重点讲评清单 ⭐教师版的核心产出

- **自动判定**：班级得分率 < 阈值（默认 70%，报告内可调，调完实时重算）
- 按得分率**升序**排列（最该讲的第一条）
- 每条包含：题号、题干摘要、班级得分率 vs 年级得分率、主错因、涉及学生数、**建议讲法**（规则化生成的文案模板）
- 操作：
  - 「加入讲评题篮」→ 对接 `index.html` 讲评页已有的题篮追踪能力（PRD F6）
  - 「导出讲评清单」→ 打印友好的 A4 版式

**这个模块是 R1 区别于参考目录原型的主要增量**：把前面 5 个模块的分析结论收敛成一份可直接带进课堂的清单，教师不需要自己在报告里翻找。

### 模块 7 · 关注学生名单

两条预警规则（单次作业口径，只依赖本次作答）：

| 规则 | 判定条件 | 需要的数据 |
|---|---|---|
| 本次低分 | 本次得分率 ≤ 70% | 本次 |
| 本次答题异常 | 未答 ≥ 2 题 或 空白率 ≥ 20% | 本次 |

每行：姓名、得分率、班级/年级排名、命中规则标签、薄弱知识点、建议动作。
点击姓名 → 学生个人报告（对接 `student-report.html`）。
**跟进闭环**：教师可标记「已谈话 / 已补练 / 已联系家长」，处理状态随本页同步刷新；不承诺跨次报告的闭环率回看。

### 模块 8 · 我的班在年级中（受限对比）

权限红线：**只给分位与均差，不列任何其他班的班名、教师名、明细数据**。

- 年级位次：第 X / N 班，或分位区间
- 与年级均差、与同类型班级均差
- 同类型班级内排名（按平行班 / 重点班分组；同类班级 < 3 个时隐藏排名，避免小样本暴露个体）

### 模块 9 · 教学建议（规则化生成，可编辑）

三段式：优先讲评题（按失分占比排序）→ 知识点补强建议 → 分层作业建议（A/B/C 层名单 + 建议题量）。
提供教师批注框，可保存并随导出一起输出。

## 四、R2 · 年级报告（学科教师版）

教师看年级报告的目的不是管理年级，而是**给自己的班找参照系**。全篇视角锁定「我的班 vs 年级」。

| # | 模块 | 内容 |
|---|---|---|
| 1 | 年级概览 | 年级均分 / 得分率 / 提交率 / 优秀率 / 及格率 / 低分率 + 四档分布；**「我的班」在分布中高亮标出** |
| 2 | 三线对比 ⭐ | 逐题得分率三线：我的班 / 年级最优班 / 年级平均；自动标出 gap 最大的 3 题 |
| 3 | 我的班排名 | 全年级排名 + 同类型班级内排名（同类 < 3 班隐藏） |
| 4 | 知识点差距 | 我的班与年级的掌握率差值排序 → 优势 TOP5 + 薄弱 TOP5 |
| 5 | 年级共性薄弱点 | 年级掌握率 < 80% **或** 薄弱班覆盖 ≥ 50% 班级的知识点 |
| 6 | 共性错因 | 跨班汇总错因分布，判断是不是全年级都踩同一个坑 |
| 7 | 对标建议 | 基于 gap 生成：「向年级最优班学什么」「哪些题是我班独有的问题」 |

**权限设计**：模块 2 的「年级最优班」是匿名聚合标签，不显示班名和教师名。教师能知道自己差在哪、差多少，但看不到具体是哪个班——这既满足参照需求，又避免教师间的横向压力。

## 五、R3 · 班级报告（领导版）

如第二节所述，R3 = **单班在年级坐标系中的质量诊断**。

### 模块 1 · 班级速览

KPI 卡 + **年级位次**（排名 / 分位 / 与年级均差 / 与同类班均差）。
与 R1 的区别：KPI 下方跟的不是「与年级对比」小字，而是**该班在年级的排名徽章**——领导第一眼要的是位次。

### 模块 2 · 班级横向对比 ⭐

全年级各班对比表 + 柱状图（seg 控件切换表格/图形）：

| 列 | 说明 |
|---|---|
| 班级 / 任课教师 | 领导版可见真实班名与教师名 |
| 平均得分率 + 排名 | 当前班高亮 |
| 与年级均差 | ±pp |
| 提交率 | 反映班级管理而非教学质量，需分开看 |
| 待及格人数 | 绝对人数，比百分比更能反映工作量 |
| 有效样本 | 配合小样本保护 |

### 模块 3 · 知识点班际差异

该班 vs 年级逐知识点对比条形图，并给出**班际极差与显著性标记**。

显著性检验是必要的：领导最容易犯的错是看到某班某知识点低 5pp 就认定教学有问题，而这可能纯属抽样波动。标记规则建议：

- `**` 差异显著（p < 0.01）
- `*` 差异可能显著（p < 0.05）
- 无标记 = 差异在波动范围内，不建议据此下结论

### 模块 4 · 质量诊断 ⭐领导版核心

对该班给出四象限判定，**每条判定都必须展示规则依据**（可展开查看计算过程）：

| 判定 | 触发条件 | 建议动作 |
|---|---|---|
| 教学有效，可推广 | 均分差高于阈值（RP_CONFIG.meanGap） + 知识点全面优于年级 | 提炼经验，安排公开课/教研分享 |
| 差异显著，需统一教研 | 班际极差大 + 显著性检验通过 | 组织集体备课，统一教学进度与方法 |
| 年级薄弱，优先补强 | 全年级该知识点均薄弱 | 不是教师问题，年级层面统一补强 |
| 局部薄弱，班内自查 | 仅本班个别知识点弱 | 提示任课教师班内自查，不上升年级 |

**「不是教师问题」这一类判定极其重要**——它把年级共性薄弱从班级责任中剥离出来，避免误伤教师，也决定了管理动作的层级。

### 模块 5 · 关注学生汇总（不下钻）

只显示**规模与结构**，不提供学生个人明细：

- 该班两类预警人数 vs 年级平均
- 跟进处理状态（该班任课教师是否在处理）

领导需要知道「这个班有多少学生需要关注、教师有没有跟进」，不需要知道具体是谁。这既是隐私边界，也符合管理颗粒度。

### 模块 6 · 督导建议

重点督导班级 / 重点督导知识点 / 建议教研落点，每条附「依据」链接回上述模块。

> 教师净偏离（生源基线）因基线数据不存在，本版整体不实现；质量判定只用均分差 + 共性薄弱命中。

### 模块 7 · 教师视角明细（折叠）

R3 面向领导，教师视角的用户、逐题、讲评清单等明细默认折叠，非重点。

## 六、R4 · 年级报告（领导版）

| # | 模块 | 内容与领导视角要点 |
|---|---|---|
| 1 | 年级概览 | 全量 KPI + **数据质量说明**（应交/实交/未批阅/空白卷/异常卷），领导看的数字必须知道口径 |
| 2 | 知识点分析 | 年级掌握率排序 + **薄弱班覆盖数** + 掌握等级分布 |
| 3 | 错因分析 | 错因 × 知识点交叉热力矩阵 + 典型错题 TOP10 |
| 4 | 班级对比 | 排名表 + 知识点热力图（班 × 知识点）+ 错因堆叠条 |
| 5 | 质量诊断 | 知识点级判定 + 督导建议 |
| 6 | 学科诊断 | 归因链 + 知识点维度概览 + 易混淆对 + 题型 × 易错点 |
| 7 | 教研落点 ⭐ | 备课主题建议 / 公开课建议 / 补题建议 / 资源推荐（对接校内资源库） |

**模块 7 是领导版最大的增量价值**：领导开完教研会要布置任务，报告直接给出「下次备课聚焦哪 3 个知识点」「谁适合开公开课」「题库缺哪类题需要补」，让分析结果直接变成会议决议。

模块 6 不设能力雷达：一个学科的知识点按业务维度归属（同步 / 复习…），维度并列、各自独立统计，一个知识点只归属一个维度，同一题可跨多个维度挂接；不设能力 / 核心素养维度，也不由知识点反推能力项，因此不依赖任何「知识点 → 能力维度」映射表。

## 七、权限矩阵

| 能力 | teacher (R1/R2) | leader (R3/R4) |
|---|---|---|
| 查看本班报告 | ✅ 完整 | ✅ 完整 |
| 查看他班报告 | ❌ 按钮不渲染 | ✅ |
| 他班班名 / 教师名 | ❌ 仅匿名聚合（「年级最优班」） | ✅ |
| 学生个人明细报告 | ✅ 本班 | ⚠️ 仅人数规模，不下钻个人 |
| 逐题下钻 / 讲评清单 | ✅ | ➖ 非重点，可折叠 |
| 显著性检验 | ❌ | ✅ |
| 教研落点 / 督导建议 | ❌ | ✅ |
| 导出 | 讲评清单 | 年级汇总表 |

**实现建议**：不做两套独立页面。R1/R3 共用 `class-report.html`、R2/R4 共用 `grade-report.html`，通过 `?role=` 参数控制模块渲染与数据脱敏。理由：
- 参考目录的 `class-report.html` 已验证此模式（`?role=leader` 时追加组长模块）
- 减少一半维护成本，避免两份页面指标口径漂移
- 权限判断集中在数据层，比在两个页面分别实现更不易出错

但需注意：**脱敏必须在数据层完成**，不能只靠前端隐藏 DOM。教师版不应把他班明细数据下发到浏览器。

## 八、指标口径与阈值配置

所有阈值不硬编码，集中到一份配置对象，支持校级统一设置：

| 配置项 | 默认值 | 影响模块 | 来源 |
|---|---|---|---|
| 等级分档边界 | 优秀 ≥90% / 良好 ≥80% / 及格 ≥60% / 低分 <30% | 得分分布、各档率 | **生产「设置等级」，直接读取** |
| 重点讲评题阈值 | 班级得分率 < 70% | 讲评清单、逐图标红 | 报告新增配置 |
| 知识点掌握分级 | 掌握 ≥80% / 薄弱 60–80% / 未掌握 <60% | 知识点诊断 | 报告新增配置 |
| 断崖下跌 pp | ↓ ≥ 15pp | 关注学生 |
| 年级共性薄弱覆盖率 | 薄弱班 ≥ 50% | R2/R4 共性薄弱 |
| 显著性水平 | p < 0.05 / p < 0.01 | R3/R4 班际差异 |
| 小样本保护线 | 有效样本 < 10 | 全局 |

### 8.1 小样本保护（必须实现）

有效样本 < 10 时：
- 隐藏排名、分位、显著性检验
- 优秀率/及格率/低分率显示为「样本不足」而非百分比
- 班级横向对比表中该行标灰并注明样本数
- 年级聚合计算时**按人数加权**，不用班级简单平均（否则 1 人班和 35 人班权重相同）

> 当前 mock 数据中 `TK-001`（total 14、submitted 1）、`HW-DFS`（total 3 / total 1）等班级都会触发此规则。这不是边缘情况，是数据现状。

### 8.2 单次作业口径（报告不依赖历史）

报告只使用**本次作业**数据，不实现跨次对比、趋势与历史预警。原依赖历史的能力按下表处理：

| 依赖历史的能力 | 本版处理 |
|---|---|
| 稳定度（近 5 次标准差） | 不实现 |
| 断崖下跌 / 首次低分 / 持续低位 | 不实现；预警只保留「本次低分」「本次答题异常」 |
| 趋势对比 / 与上次差值列 | 不实现，不出现在页面上（不是显示 —） |
| 跟进闭环率跨次回看 | 不实现 |

原则：这不是数据缺口导致的降级，而是产品口径——报告定位为单次作业的教学决策工具；跨次分析需另立产品或另行立项。

## 九、数据模型补充需求

### 9.1 需要新增的数据层

```js
// L1 题目层
QUESTIONS: [{ no, type, score, kp, classRate, gradeRate, cause, options[] }]

// L2 知识点层

// L4 错因层
CAUSES: [{ n, cnt, stu, qs[], kp, lostScore }]

// L5 历史层（接口桩，本版不消费；单次口径不做跨次对比）
PREV: []

// L6 配置层
CONFIG: { thresholds{}, gradeGroups{} }
```

### 9.2 现有可复用资产

`main.js:37-49` 的 `studentData` 已具备学生层的大部分字段形态：

```
name, examNum, eduNum, score, objScore, subjScore,
jointRank, gradeRank, classRank, grade,
detailScores[], detailOptions[], typeScores{}, status
```

- ✅ 可作为 L3 的结构蓝本，字段命名直接沿用
- ⚠️ 但它属于讲评页（`index.html`）的 mock，**没有作业 ID 关联**，只有约 15 条
- 迁移方式：抽出为独立数据模块，增加 `hwId` 与 `cls` 外键，扩展到全量学生

### 9.3 数据缺口清单（按优先级，已按生产截图修订）

生产已确认具备：学生级成绩（原始成绩 tab）、提交/未交名单与异常学号标注、等级档位聚合与排名、题级错题信息（本次错题 tab）。因此报告侧的 P0 不是"建新数据"，而是**与讲评页同源接入**。

| 优先级 | 数据 | 状态 | 阻塞的报告能力 |
|---|---|---|---|
| P0 | 与讲评页同源接入（学生级成绩 / 题级错题 / 等级配置 / 提交名单） | ✅ 生产已具备，接入方式待确认 | 几乎全部指标计算 |
| P0 | 题目 ↔ 知识点映射（含知识点所属维度字段） | ⚠️ 未确认 | 知识点诊断、共性薄弱、学科诊断（维度概览） |
| P1 | 答题时长（开始/结束时间戳） | ⚠️ 未确认 | 用时指标、答题异常判定 |
| P1 | 错因分类体系与标注 | ⚠️ 部分具备（有错题信息，错因分类体系未确认） | 错因聚类、交叉矩阵 |
| P2 | 班级分组（平行班/重点班） | ⚠️ 未确认 | 同类型班级内排名 |
| P2 | 校内资源库 | ⚠️ 未确认 | R4 教研资源推荐 |

**唯一的硬缺口是题目 ↔ 知识点映射**：它缺失时报告将退化为「分数 + 分布 + 排名」报告，知识点维度整体不可用。这是本方案最大的功能风险，建议列为 P0 确认项；若短期拿不到，知识点相关模块按 8.2 的边界声明隐藏而非给空数据。

## 十、交互与技术落地

### 10.1 页面与跳转

| 项 | 约定 |
|---|---|
| 新增文件 | `class-report.html`、`grade-report.html`（各承载两个角色） |
| 跳转方式 | 同窗口 `location.href`（与 `goLecture()` 一致） |
| URL 参数 | `?hw=<作业ID>&cls=<班级>`，年级报告省略 `cls` |
| 角色透传 | 复用现有 `withRole()` |
| 下钻链路 | 年级 → 班级 → 学生（`student-report.html?hw=&cls=&si=&nm=`） |
| 返回 | 面包屑 + 浏览器后退，报告页需保留列表页的筛选与展开状态（可用 sessionStorage） |

`actOn()` 改造点：把「班级报告」「年级报告」两个分支的 toast 替换为跳转，**保留现有的可点性判断与批阅状态提示逻辑**。

### 10.2 视觉规范（对齐本项目，而非参考目录）

| 项 | 参考目录 | 本项目应采用 |
|---|---|---|
| 主色 | Ant Design `#1890ff` | `--primary-color: #3b82f6` |
| 领导版配色 | 独立紫色 `#722ed1` | **不引入第二套主色**，用 R3/R4 徽章 + 顶部色条区分 |
| 全局导航 | 无 | 必须套 `global-nav.css` / `.topnav`，与 `index.html` 统一 |
| 字体 | — | Inter + Noto Sans SC（沿用） |

> 领导版沿用主色系而非另起紫色，是为了不破坏 `global-nav.css` 已经建立的视觉统一。角色区分交给徽章和顶部色条，成本更低、辨识度足够。

### 10.3 图表技术选型

两个选项：

| 方案 | 优点 | 缺点 |
|---|---|---|
| 纯 SVG 手绘（参考目录做法） | 零依赖、体积小、打印友好、样式完全可控 | 复杂交互（缩放、tooltip 联动）需自己写 |
| ECharts（本项目已有 `echarts.min.js`） | 交互能力强、开发快 | 1MB 依赖、打印需额外处理、`list.html` 当前未引入 |

**建议纯 SVG**：参考目录的 6 份原型已用 SVG 完整实现了柱状图、环形图、雷达图、热力图、堆叠条、四象限气泡图，可直接迁移；且报告页有明确的打印/导出需求，SVG 在 `@media print` 下表现更稳定。ECharts 留给 `index.html` 讲评页的关系图等强交互场景。

### 10.4 通用交互约定

- 顶部 sticky 锚点导航（带序号徽章），模块多时快速定位
- seg 分段控件：表格 ↔ 图形切换
- 抽屉：讲评清单、预警规则口径说明
- 弹窗：知识点明细、错因明细
- 折叠区：页面底部「数据质量说明」，样本口径透明化
- `@media print`：隐藏导航与按钮，折叠区强制展开
- 响应式：767px 以下隐藏 PC 图表并给出提示（或提供移动版简表）

### 10.5 待确认项

1. 用户选中元素的 HTML 含 `class="act pi-selected"`，但当前 `list.html` 与 `style.css` 中**均无 `pi-selected` 类**。疑为设计稿标注或预览态残留，需确认是否要实现「选中态」样式。
2. 「单词作业」在本方案中按**单次作业**理解（参考目录文件名为 `班级单次作业报告.html`，且按钮调用形态为单作业+单班级）。若实指英语单词/词表默写类作业，指标体系需重做——单词作业的知识点粒度是「词」而非「题」，会增加「错误拼写 TopN」「音形义混淆对」「词频分级掌握度」等专属维度。
3. 领导角色是否需细分「学科组长 / 教务主任 / 校领导」三级。当前只有 leader 一档，若校领导需要更宏观的跨学科视图，R4 之上还要再加一层。

## 十一、分期建议

| 期次 | 内容 | 前置条件 |
|---|---|---|
| **P0** | R1 班级报告：概况 + 得分分布 + 逐题得分率 + 重点讲评清单 | 与讲评页同源接入（生产已具备学生级成绩与题级错题） |
| **P0** | R4/R2 年级报告：年级概览 + 班级对比 + 三线对比 | 同上 |
| **P0** | 确认题目 ↔ 知识点映射可得性 | 决定知识点维度是否进 P0，否则按 8.2 边界声明隐藏 |
| **P1** | R1 补全：知识点诊断、错因聚类、关注学生（本次规则） | 知识点映射、错因标注、答题时长 |
| **P1** | R3 领导版班级诊断：横向对比 + 质量诊断四象限 | 显著性检验、班级分组 |
| **P2** | R4 教研落点、资源推荐 | 资源库对接 |
| **另立项** | 跨次趋势、断崖/持续类预警、教师净偏离 | 历史作业数据累积 ≥ 3 次；生源基线数据 + 校级决策 |

P0 的目标是**让教师下节课就能用上**——概况、分布、逐题、讲评清单这四个模块构成一个完整闭环，不依赖任何历史数据。
