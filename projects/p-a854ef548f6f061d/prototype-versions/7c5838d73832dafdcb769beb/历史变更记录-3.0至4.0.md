## 1. 背景与问题

### 1.1 升级动因

题库侧知识图谱完成升级：知识点之间不再是孤立的层级树节点，而是携带**前序（前置依赖）、后序（后续应用）、易混淆**等教研标注关系。讲评页面必须承接这批关系数据，否则升级只停留在"图谱页面更好看"，不产生教学动作。

### 1.2 讲评试卷 2.2 的四个缺口（升级要解决的问题）

| # | 缺口 | 现状表现 | 后果 |
|---|------|---------|------|
| 1 | 只知"哪里错"，不知"先补什么" | 知识点明细只展示当前知识点的得分率，前置基础是否薄弱无从查证 | 教师把综合题失分误判为"综合能力差"，实际可能是前置不牢 |
| 2 | 讲评顺序 = 题号顺序 | 课件按题号排列 | 前置没讲就讲综合题，讲评效率低 |
| 3 | 加练目的单一、全班同练 | "类题加练"只有一类题、默认整班 | 前置薄弱的学生补不上，已掌握的学生做无效重复 |
| 4 | AI 解读给结论不给证据 | "三角函数薄弱"式断言 | 无作答证据的前置被直接判定为薄弱，教师无法核验、无法行动 |

### 1.3 产品目标

把作业讲评从 **"知道哪里错了"** 升级为：

```
发现薄弱知识点 → 检查前置证据 → 决定讲评顺序 → 分组补练 → 复测验证是否补上
```

### 1.4 核心原则（贯穿全部功能的红线）

1. **证据链驱动**：每个结论必须挂证据。**无作答证据 = 未知，不代表未掌握**，先诊断再下结论。
2. **关系必须教研确认**：目录/教材的章节相邻顺序 ≠ 学习依赖关系。未经教研标注的"前序后序"不得用于归因。
3. **未学内容只衔接**：教学进度未覆盖的后序知识点，只做课堂预告，不布置加练。
4. **原题订正 ≠ 掌握**：重做原题正确只记"订正完成"，必须换情境复测通过才计为掌握。
5. **按学生分组证据处理**：班级均值偏低 ≠ 人人有问题；综合题失分 ≠ 其关联的所有知识点都薄弱。

## 2. 名词定义

| 名词 | 定义 | 原型中的视觉 |
|------|------|------------|
| 前序（prev） | 前置 → 当前，掌握它是学好当前知识点的先决条件 | 关系图蓝线箭头；诊断抽屉"前置"蓝 chip |
| 后序（next） | 当前 → 后续，当前知识点掌握后的迁移应用方向 | 关系图绿线箭头；"后续"绿 chip |
| 易混淆（confuse） | 与当前知识点易混淆的辨析对象 | 关系图橙色虚线；"易混淆"粉 chip |
| 证据状态 | 知识点作答证据的三种取值，见 2.1 | — |

### 2.1 证据状态（三种）

| 状态 | 含义 | 徽章样式 | 支撑的动作 |
|------|------|---------|-----------|
| 本次考查（exam） | 本次作业有独立作答记录 | 蓝 `本次考查` | 直接归因、讲评 |
| 待诊断（none） | 本次作业无任何作答记录 | 橙 `待诊断` | **只能先诊断**，禁止直接下“未掌握”结论 |
| 未学·仅衔接（unlearned） | 教学进度未覆盖 | 灰 `未学·仅衔接` | 仅课堂预告，不加练 |

> 单次作业口径：不引入往次作业 / 考试数据，证据只源于本次作答；“未知 ≠ 未掌握”。

### 2.2 五种加练目的

| 目的 | 代码 | 触发条件（证据规则） | 颜色 |
|------|------|--------------------|------|
| 前置诊断 | diag | 当前失分 且 前序=待诊断 → 用少量小题判断是否需要补基础 | #f59e0b |
| 概念辨析 | confuse | 存在易混淆关联 且 本次辨析题失分 → 成对对比练习 | #ec4899 |
| 同点巩固 | solid | 前置待诊断、当前偏弱 → 巩固当前知识本身 | #3b82f6 |
| 后续应用 | next | 当前表现稳定 → 检查迁移、适度提高 | #22c55e |
| 复测验证 | retest | 补练完成后 → 同目标、换情境新题验证 | #8b5cf6 |

### 2.3 三类学生分组（按知识点作答证据，非总分分层）

| 分组 | 判定 | 对应加练目的 |
|------|------|------------|
| diag 组 | 当前失分，且前置无证据 | 前置诊断 |
| solid 组 | 当前偏弱，前置暂无证据（不预设前置薄弱） | 同点巩固 |
| next 组 | 当前稳定 | 后续应用 |

## 4. 功能需求

### F1 知识点明细 · 关联诊断列（P0）

**功能**：知识点明细表新增「关联诊断」列（置于"未掌握名单"之后）。

**规则**：
- 有教研标注关系的知识点：显示可点击按钮 `🔗 关联诊断`，副标题显示关系计数 `前N·后N`（易混淆计入悬浮提示）。
- 无关系的知识点：显示灰色的 `—` 占位。
- 一/二级知识点的关系统计 = 其下属三级知识点关系的**去重聚合**（剔除模块内自关联）。
- 点击 → 打开 F2 诊断抽屉。

**验收**（已实测）：明细表 10 行全部渲染，三角函数行显示"前2·后2"，集合与逻辑行"前1·后1"。

### F2 关联诊断 · 右侧抽屉侧窗（P0）

**功能**：单个知识点的证据全景 + 分组处理建议。**展示形态为右侧抽屉侧窗（非居中弹窗）**：宽 min(560px, 94vw)、全高、从右侧滑入滑出，不遮挡主页面（无全屏遮罩），教师可边看图谱/明细边查证据；与补练题篮抽屉同一交互语言。

**结构**（自上而下）：
1. **知识点头部**：层级徽章、名称、本次证据（题号）、班级得分率与档位、未掌握人数。
2. **聚合提示**（仅一/二级知识点）：说明关联由子知识点汇总。
3. **前序区**：逐行展示前置知识点，每行 = 关系 chip + 名称 + 证据徽章 + 证据明细 + 按证据状态生成的操作按钮：
   - 待诊断 → 「诊断题预览」+「加入前置诊断」（快捷入题篮）
   - 本次考查 → 「查看该知识点诊断」（抽屉内切换目标知识点）
   - 前置无本次证据 → 文案“前置暂无作答证据，先诊断再决定是否补练”（无补练按钮）
4. **易混淆区**（存在时）：辨析题预览入口。
5. **后序区**：
   - 未学 → 文案"未学内容，仅课堂衔接预告，不布置加练"（无按钮）
   - 已考查 → 跳转诊断
   - 其他 → "当前掌握后再安排" + 后续应用选题入口
6. **学生分组建议**：diag / solid / next 三卡片，含学生名单 chips、分组理由、“生成本组加练”按钮；名单为空的组用理由文案代替（如“前置暂无作答证据，先诊断再决定”）。
7. **判断边界提示**（固定红线条）：综合题失分≠全关联薄弱；班级均值≠人人有问题；无证据=未知。
8. **底部操作条**：关闭 / 「生成分目的加练建议」（→ F5），sticky 贴底常显（内容滚动时始终可点）。

**交互**：
- 从 F3 关系图点击节点进入时，可携带 `focusRelId`，抽屉打开后自动滚动到对应关系行并橙色高亮 2.4 秒（滚动定位在抽屉内部滚动容器中完成）。
- 抽屉互斥规则：打开诊断抽屉会同时关闭加练弹窗与题篮抽屉；打开题篮抽屉也会先收起诊断抽屉，避免两抽屉重叠遮挡。

**验收**（已实测）：三角函数诊断 = 4 条关系行（前序 2 + 后序 2）+ 4 张分组卡；`focusRelId` 高亮定位在抽屉内滚动生效（目标行进入可视区 + 高亮生效）；抽屉右侧贴边全高（560px），底部操作条 sticky 常显；双向互斥验证通过。

### F3 知识点图谱 · 三视图（P0）

**功能**：图谱 Tab 提供三种同题库知识图谱的视图切换：「树状图 / 放射图 / 力导向图（关系图谱）」，与题库知识图谱工具的布局形态对齐。

**工具栏**：
- 视图切换组（三按钮，tab 语义，aria-selected 同步）：树状图（默认）/ 放射图 / 力导向图（关系图谱）。
- 汇总 chips：本次考查数、前序关联数、后序关联数、易混淆数、**待诊断数（橙色警示）**、未学数。

**统一点击行为（三视图一致）**：点击任意知识点节点 → 右侧关联诊断抽屉（F2）；树/放射图节点已关闭折叠切换（expandAndCollapse:false），避免"点击既是展开又是诊断"的歧义。

**树状图**：原层级树，每棵一级知识点独立横向展开（按掌握档位着色）；支持缩放拖拽（roam）；容器底部提供视图说明与点击提示条。

**放射图**：虚拟根「知识体系」居中，全部知识点按子孙规模分配角度扇区、逐层同心向外展开（同题库图谱的放射布局）；支持缩放拖拽；实现说明：因 ECharts tree series 的 orient:'radial' 在 5.x/6.x 均存在渲染层崩溃问题，采用 graph series + 手算同心坐标（layout:'none'）实现，label 按象限自动定位、重叠自动隐藏。

**本次作业关系图（力导向）**：
- **节点**：本次考查知识点（按掌握档位着色，尺寸 36）+ 图谱扩展节点（前序/后序/易混淆引用，尺寸 26）。待诊断浅灰；未学浅灰 + 浅字。
- **节点标签**：证据摘要随行（待诊断 / 未学）。
- **边**：层级归属灰线（无箭头）、前序蓝线箭头（前置→当前）、后序绿线箭头（当前→后续）、易混淆橙色虚线。
- **交互**：悬浮 tooltip 显示证据明细与"点击查看关联诊断"；点击考查节点 → 该知识点诊断抽屉；点击扩展节点 → 其宿主知识点的诊断抽屉并高亮该行。支持缩放拖拽（roam）。
- **图例**：掌握档位 + 本次考查/待诊断·未学 + 三种关系线型示例。
- **声明文案**（图下方固定）：关联节点不计入本次考查知识点数与得分统计；数据为原型模拟。

**验收**（已实测）：19 节点 / 20 条边（4 树边 + 8 前序 + 7 后序 + 1 易混淆），与数据层精确吻合；汇总 chips 数值正确；切换时容器尺寸 1103×540，resize 监听生效。

### F4 讲评课件 · 依赖排序与讲评路径（P0）

**功能**：讲评课件排序下拉新增「按知识依赖顺序（推荐）」，选中后：

1. **讲评路径条**：横向步骤条，编号 + 阶段名（+题号），示例 9 步：
   `基础订正 → 前置回顾 → 原题讲评 → 迁移检查 → 现场摸底 → 概念辨析 → 概念辨析 → 步骤规范 → 后续衔接`
   配说明文案：先补共同前置 → 原题讲评 → 换情境迁移检查 → 无证据项现场摸底 → 概念辨析 → 步骤规范 → 未学内容仅衔接预告。
2. **卡片重排**：阶段说明卡（前置回顾/现场摸底/后续衔接，含建议与时长）插入题目卡之间，题目卡带阶段徽章与讲评建议（如"历史证据偏弱，先花 5 分钟回顾再讲原题"）。
3. 切回「按题号排序」：隐藏路径条，恢复 6 张题卡原序。

**规则**：路径顺序由知识依赖 + 证据状态生成（前置弱先讲、无证据项插讲评中现场摸底、未学项固定末尾），教师可自行调整课堂节奏（原型不锁定顺序）。

**验收**（已实测）：路径条 9 步、阶段卡 3 张、题目卡 6 张、阶段徽章 9 处。

### F5 分目的加练弹窗（P0）

**功能**：从「类题加练」升级为按目的分区的选题主面板。

**结构**：
- 每个目的一个区块（按 diag → pre → confuse → solid → next 排序，仅有题的目的显示）：
  - 目的徽章 + 一句话策略说明（如"前置暂无证据 → 用少量小题判断是否需要补基础"）
  - **风控警示**：当前得分率 <80% 时，后续应用区显示"建议先完成同点巩固"
  - **布置范围选择**：`仅名单学生（N人）` / `全班共练`（默认取分组名单）
  - 名单学生 chips
  - 题目卡：勾选框 + 题号 + 题型/难度/预计时长/目标知识点 + 题干 + 推荐目的 + 推荐依据
- **复测区**（存在复测题时）：「同时生成复测任务」开关（默认开）+ 复测题标签 + 规则文案"原题订正只记订正完成，不计为掌握"。
- **底部**：实时计数 `已选 N 题 · 预计 M 分钟（含复测）`、取消、加入题篮。
- 勾选联动：从诊断抽屉指定目的/关系进入时，对应目的自动勾选、目标题目高亮。

**验收**（已实测）：三角函数 = 2 目的区块（前置诊断 D-03 / 同点巩固 S-31、S-32）+ 复测 R-31；默认勾选 4 题 17 分钟（3+3+8+3），与题库分钟数精确一致。

### F6 补练题篮（P0）

**功能**：右下角常驻 FAB（徽章计数）+ 右侧抽屉。

**抽屉结构**：
1. **待确认区**：每组 = 目的徽章 + 知识点 + 范围（名单N人/全班）+ 移除按钮 + 名单 chips + 题目标签（`题号·题型·难度·Nmin`）+ 预计负担（题数·分钟·复测提示）。
2. **补练追踪区**（确认布置后）：每组三步状态条 `已发布 → 补练进行中 → 待复测（复测批阅）`，绿色底纹区分。
3. **底部**：清空 / 确认布置（题篮为空时禁用置灰）。

**交互**：
- 加入题篮 → Toast 提示 + FAB 徽章更新。
- 确认布置 → 待确认组转入追踪区，Toast"已布置 N 组补练（原型模拟，未真实下发）"。
- 复测组加入规则：自动汇总本次该知识点已加入的名单学生作为复测对象。

**验收**（已实测）：诊断快捷加入 1 组 → 分目的加入 3 组 + 复测 1 组 = 5 组 26 chips 6 题；布置后 5 组全部进入追踪区，三步状态条渲染正确。

### F7 学生详情 · 学习路径（P0）

**功能**：学生详情弹窗新增「学习路径」区块（按本次均分三档生成）：

| 档位 | 目标 | 路径步骤 |
|------|------|---------|
| ≥85 | 后续应用（利用奇偶性求参数/三角函数综合） | 本次表现核查(已完成) → 后续应用练习 → 复测验证 |
| 60–84 | 同点巩固（奇偶性判定/三角函数同角关系） | 本次作答证据核查(已完成) → 同点巩固 → 复测验证 |
| <60 | 当前失分知识点，前置待诊断 | 前置诊断 → 按诊断结果决定是否补练 → 同点巩固 → 复测验证 |

节点样式区分已完成/进行中/待开始；固定说明"路径依据知识图谱前后序关系与作答证据生成；待诊断=暂无证据，先诊断再决定是否补练"。

**验收**（已实测）：低分生 4 步（诊断→补练→巩固→复测）、高分生 3 步（1 done 2 todo），差异化正确。

### F8 AI 解读 · 证据链重构（P0）

## 5. 数据需求

### 5.1 原型模拟数据结构（main.js 已实现，真实接入时替换）

```
KP_RELATION_NODES        关联知识点池（本次未考查的扩展节点）
  { name, evidence: exam|none|unlearned, rate?, questions?, kind? }

KP_RELATIONS             知识点关系（按三级知识点标注）
  { '2-2': { prev: [...], next: [...], confuse: [...] } }

KP_STUDENT_GROUPS        学生分组证据（按知识点 × 三类路径）
  { '2-2': { diag: {students, reason}, solid: {...}, next: {...} } }

DRILL_BANK               分目的题库
  diag / confuse / solid / next / retest 五桶
  题目字段：{ id, type, diff, minutes, stem, purpose, reason, target? }

PURPOSE_META             目的元数据（label / color / desc）
```

### 5.2 真实接入的数据要求（P1）

| 数据 | 要求 |
|------|------|
| 知识点关系 | 必须来自教研标注（支持审核状态字段），禁止由目录顺序自动生成；关系变更需留痕 |
| 证据状态 | evidence 由本次作业作答记录推导：本次命中→exam；未命中→none；教学进度未覆盖→unlearned。不引入往次考试数据 |
| 题库目的标签 | 每道题至少一个目的标签 + 推荐依据 reason（供教师核验） |
| 复测题 | 与原题同知识点、不同情境，需与原题建立关联映射 |
| 学生分组 | 按知识点粒度的作答结果推导，非总分分层；名单可教师手工增删 |

### 5.3 聚合与校验规则（已实现）

- 一/二级知识点关系 = 子孙三级知识点关系去重聚合，剔除模块内自关联；
- 关系图中扩展节点**不计入**本次考查知识点数量与得分统计；
- 预计时长 = 勾选题 minutes 之和（含复测开关），实时联动。

## 7. 原型边界声明（不可当真实依据的部分）

1. 全部关系、证据、题目、分组均为**模拟数据**（页面顶部原型声明横幅已按需求移除，模拟数据声明保留于 AI 证据链"生成说明"处）。
2. 知识点掌握度（mastery）与模块得分数值为模拟数据，不代表任何真实学情。
3. "确认布置"仅改变本地状态（待确认→追踪），不真实下发学生任务。
4. 复测通过/未通过流转为文案模拟，无真实批阅回写。
5. **特别提醒**：参照用 知识图谱.html 的关系由目录相邻节点生成，不能当作教研确认的依赖关系使用。
